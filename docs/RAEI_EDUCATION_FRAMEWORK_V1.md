# RAEI Education Framework V1.0

## 1. Objective
Develop demonstrable engineering capability from computing fundamentals through advanced software and security engineering, then apply it responsibly to RhemaScript. Education is competency-based, not a claim based on reading time or book counts.

## 2. Teaching method
Every learning unit follows: prerequisite diagnostic → lesson from first principles → lawful reference study → explained examples → independent practice → practical project → assessment → targeted remediation → evidence record → later retention check. Use unfamiliar problem variants to test transfer, not memorisation. Adapt the starting level to demonstrated ability.

## 3. Progressive school-to-postgraduate curriculum

### Level 0 — Logic and learning foundations
Precise instructions, reading comprehension, arithmetic, patterns, sets, propositions, truth tables, decomposition and basic probability. Exercise: convert ambiguous requests into inputs, outputs, constraints and testable requirements.

### Level 1 — School mathematics and computer fundamentals
Algebra, geometry, functions, graphs, discrete reasoning, binary/hexadecimal, Boolean logic, statistics, computer components, CPU, memory, storage, files, operating systems and network basics. Exercise: trace logic and explain how a computer represents and executes information.

### Level 2 — Programming foundations
Pseudocode, algorithms, Python, variables, types, control flow, functions, collections, strings, files, exceptions, debugging, command line, Git and introductory tests. Exercise: independently build small programs from written requirements, including invalid-input handling.

### Level 3 — Undergraduate computer science
Data structures, algorithms and complexity, programming paradigms, SQL and databases, computer architecture, operating systems, networks, concurrency, compilers/language concepts, software engineering, testing and computing mathematics. Exercise: build and test a modular application and justify design choices.

### Level 4 — Advanced/postgraduate study
Distributed systems, database internals, transactions, consistency, advanced algorithms, formal methods, programming language theory, applied cryptography, machine learning, information retrieval, privacy, fault tolerance and reliability. Exercise: design a system with explicit failure, consistency and security reasoning.

### Level 5 — Professional engineering
Secure SDLC, threat modelling, identity/access management, authorisation, secrets, supply-chain security, CI/CD, observability, incident response, performance, code review, release/rollback, licensing and technical leadership. Exercise: conduct a security review and deliver a traceable, tested bounded change.

### Level 6 — RhemaScript domain engineering and research
Study existing RhemaScript architecture, capabilities, interface contracts, Scripture-centred workflows, source-to-final provenance, evidence, six approval gates, security/trust and production learning. Exercise: propose a non-duplicative design, implement an authorised isolated enhancement, demonstrate authority denial and produce a full evidence chain.

## 4. Languages and tools
Begin with Python because the current repository baseline requires Python 3.11+ and declares no runtime dependencies. Teach SQL, shell and Git; add TypeScript/JavaScript or other languages only when justified by an approved requirement. Teach editors, debuggers, version control, test runners, static analysis, dependency scanning, CI and observability. Prefer free/local tools and lawful open resources; do not add paid services, external integrations or dependencies merely for education.

## 5. Curated reading and reference library
This is a syllabus, not a claim that RAEI has read or mastered the works. Verify edition, current relevance, lawful access and licence before use. Do not copy entire copyrighted books into the repository without permission; retain bibliographic metadata and lawful references.

**Foundations:** *Code: The Hidden Language of Computer Hardware and Software* (Charles Petzold); *Computer Science: An Overview* (Brookshear and Brylow); *Structure and Interpretation of Computer Programs* (Abelson and Sussman); *Computer Systems: A Programmer's Perspective* (Bryant and O'Hallaron); *Introduction to Algorithms* (Cormen, Leiserson, Rivest and Stein).

**Programming and engineering:** *Think Python* (Allen Downey); *The Pragmatic Programmer* (David Thomas and Andrew Hunt); *Code Complete* (Steve McConnell); *Software Engineering at Google* (Titus Winters, Tom Manshreck and Hyrum Wright); *Clean Architecture* (Robert C. Martin), read critically and compared with contemporary practice.

**Architecture and data:** *Designing Data-Intensive Applications* (Martin Kleppmann); *Fundamentals of Software Architecture* (Mark Richards and Neal Ford); *Release It!* (Michael T. Nygard); official Python, PostgreSQL and Git documentation.

**Security:** *Threat Modeling: Designing for Security* (Adam Shostack); *Security Engineering* (Ross Anderson); *Alice and Bob Learn Application Security* (Tanya Janca); OWASP ASVS, OWASP Cheat Sheet Series, OWASP Top 10; NIST SP 800-218 Secure Software Development Framework; CISA Secure by Design; official cryptographic standards and vetted library documentation.

**Formal methods and AI:** *Specifying Systems* (Leslie Lamport); *Designing Machine Learning Systems* (Chip Huyen); relevant official documentation and peer-reviewed research.

## 6. Competency assessment
Score each applicable dimension 0–4: conceptual understanding; independent reasoning; correctness; code quality; testing/debugging; security/privacy; architecture/trade-offs; documentation/evidence integrity. 0 = absent/unsafe; 1 = major gaps; 2 = partial with supervision; 3 = independently competent for assessed scope; 4 = strong transferable mastery on unfamiliar work.

Provisional pass requires at least 3 in every applicable dimension, no critical failure and retained evidence. Any critical authority bypass, fabricated evidence, exposed secret or knowingly unsafe security regression is an automatic failure. High-risk work also requires independent human review.

Record assessment ID/version, date, source commit, objectives, task variant, permitted resources, commands/environment, outputs, tests, rubric scores, reviewer, remediation and reassessment. Do not store credentials, secrets or unnecessary personal data.

## 7. Learning from mistakes
Record expected versus observed behaviour, reproduction evidence, root cause, correction, regression test, lesson and reassessment. A lesson is not learned merely because it was written down. It must be demonstrated. Learning records do not amend the Constitution or grant authority.

## 8. Teaching modes
- **RAEI LEARN:** teach, practise and assess.
- **RAEI BUILD:** apply knowledge to authorised implementation.
- **RAEI AUDIT:** inspect and report evidence-based findings.
- **RAEI EXAM:** run unfamiliar practical/conceptual assessments.
- **ACTIVATE RAEI / DEACTIVATE RAEI:** enter/leave conversational engineering mode.

These are conversational modes, not a persistent background process or model-weight retraining.

## 9. Baseline and capstone
First assess logic, Python comprehension, algorithms, Git, architecture, debugging, security and understanding of RhemaScript capabilities/interfaces/gates. Assign a starting level per subject, not one assumed level for everything.

Capstone: a bounded, non-consequential RhemaScript enhancement on an isolated branch. RAEI must inspect architecture, justify reuse, document design/threat model, implement maintainably, add positive/negative/boundary/regression tests, run CI, provide commit and test evidence, state limitations and preserve all authorities. Passing proves only the assessed scope and does not grant merge/deploy/generation/publishing/spending permissions.

## 10. Maintenance
Version curriculum updates. Changes to learning outcomes, thresholds or governance boundaries require rationale and review. Constitution governs if a conflict arises.
